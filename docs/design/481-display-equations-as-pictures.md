# 481 — 따로 선 수식은 논문 그림 그대로 문장 아래에 보여 준다

## 문제

사용자: "논문에서 수식 같은 것은 거의 대부분 분석을 못하더라고." 글자 뽑기(Azure layout, PyMuPDF)는
분수·근호·합 기호를 한 줄 글자로 옮기지 못한다. 그래서 `section_flow._is_display_math` 가 따로 선
수식 칸을 버리고 있었다. 버릴 때 그 칸의 쪽과 자리도 같이 버려서, 문장 사이에서 수식이 그냥 사라졌다.

## 방침

1. **칸을 버리지 않고 기억한다** — `collect_equations` 가 버려지는 수식 칸의 쪽·사각형과 바로 앞
   문단 끝 글자 40개, 바로 뒤 문단 첫 글자 40개를 남긴다. 한 쪽에서 붙어 있고 사이에 글이 없는 수식
   칸은 하나로 합친다(단 사이에서 끊긴 수식, 오른쪽 번호 `(3)`). 번호만 홀로 있으면 수식이 아니다.
   제목·쪽 머리·각주 역할 칸과 `2.1.2. Synthesis of Al–Ce–O` 같은 번호 제목은 기호가 있어도 빼고,
   참고문헌 안은 보지 않는다. 그림 안의 기호 꼬리표는 이미 그림 칸이라 들어오지 않는다.
2. **어느 문장 뒤인지 정한다** — `place_equations` 는 논문 전체에서 구절을 찾지 않는다. 읽는 순서로
   앞 수식 자리 다음부터만 찾고, 앞 글 끝 글자(40·24·16자)로, 안 되면 뒤 글 첫 글자로 찾는다. 같은
   문단 뒤의 수식 여러 개는 같은 문장에 붙는다. 못 찾으면 붙이지 않는다.
3. **그림으로 자른다** — `render_equations` 가 PDF 에서 그 사각형(+3pt)을 3배(216dpi) 회색 PNG 로
   자른다. 하나 150 KB, 논문 하나 1.2 MB 넘으면 버린다(보통 하나 2~9 KB). 문장 행에
   `equations: [{id, src(data URL), w, h(쪽 위 크기, pt)}]` 로 실린다. 서버 저장본, 이어 받기
   payload, 폰 저장본 모두 같이 들고 간다.
4. **읽기 화면** — `SentenceEquations` 가 문장 바로 아래(번역 위) 가운데에 그림을 놓는다. 크기는
   논문 본문 9.5pt 글자가 문장 글자 크기로 읽히게 맞추고, 칸보다 넓으면 줄인다. 색은 테마에 맞춘다:
   흰 바탕은 카드 색, 검정은 글자 색(`ColorFilter.matrix`). 어두운 테마·종이 테마에서도 하얀 네모가
   뜨지 않는다.
5. **건드리지 않는 것** — 읽어 주기, 번역, 연습은 문장 글자만 본다. 문장 안의 작은 수식(인라인)은
   그대로다. 수식을 LaTeX 로 바꾸는 Azure formulas 추가 기능(쪽당 비용)과 `flutter_math_fork` 는 이번에
   쓰지 않는다.

## 남은 것

- 이미 분석한 논문은 **다시 분석** 해야 수식이 붙는다.
- 레이아웃 칸이 없는 길(Azure 없이 PyMuPDF 만)에서는 아직 수식을 모른다.
