# 446 — 논문 가져오기 검색 · 폴더 변경은 한 단계 위에서 (0.3.471)

## 1. 검색

### 문제

폴더에 PDF가 많으면 원하는 논문을 눈으로 찾아야 했다.
화면에 크게 보이는 제목은 앱이 인식한 제목이라 파일 이름과 다르다.

### 바꾼 것

- 필터 버튼 위에 검색창. 파일 이름과 인식한 논문 제목을 둘 다 본다 (`matchingSearch`).
- 본문+SI 묶음은 두 파일의 이름과 제목을 모두 본다.
- 단어를 여러 개 치면 순서와 상관없이 모두 들어간 줄만 남는다.
- 대소문자를 가리지 않는다. 제목에 인쇄된 여러 가지 줄표(‐ – — −)는 `-`로 친 것과 같다.
- 검색은 '미보관만'·'안 읽음만' 필터와 함께 걸린다.
- 검색어는 기억하지 않는다. 화면을 다시 열면 비어 있다.
- 검색으로 가려진 줄도 고른 상태는 남고, '대기열에 추가'는 가려진 것까지 함께 넣는다.
  그래서 `_enqueueSelected` 에는 검색 전 목록(`built.items`)을 넘긴다. 묶음이 낱개로 쪼개지지 않는다.

제목을 아직 인식하는 중인 파일은 끝나기 전까지 파일 이름으로만 찾힌다.

## 2. 폴더 변경

### 문제

'폴더 변경'은 현재 폴더에서 열리게 하려고 연결된 폴더의 tree URI를 `EXTRA_INITIAL_URI` 로 넘겼다.
폴더 선택 화면은 tree URI를 받지 않아 기본값인 다운로드가 열렸다.

### 바꾼 것

- `pickTree(openParent: true)` 이면 `SafTreeHandler.parentDocumentUri` 가 현재 폴더의 한 단계 위 폴더를
  document URI 로 만들어 넘긴다. 예: `primary:Download/박사님 작성 논문` → `primary:Download`.
- 폰 저장소(`com.android.externalstorage.documents`)만 문서 id 에 경로가 들어 있다.
  다른 곳(드라이브 등)은 위 폴더를 알 수 없으므로 전처럼 다운로드가 열린다.
- '다운로드 변경'은 바꾸지 않았다.

안드로이드 11부터 다운로드 폴더 자체와 저장소 맨 위는 고를 수 없다. 위 폴더가 그곳이면 목록은 보이고 그 안의 폴더를 고른다.
