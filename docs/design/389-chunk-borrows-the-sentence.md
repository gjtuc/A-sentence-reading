# design/389 — 덩어리는 문장의 기준 소리를 빌린다

## 문제

미리 짓기(design/378·385)는 문장 전체를 짓는다. 연습은 문장을 앞부분부터 늘려 가는 덩어리로 읽는다 (`shadowing_chunks.py` — 각 덩어리는 앞 덩어리로 시작하고 마지막은 문장 전체). 기준 소리는 글자 그대로로 찾으니 덩어리마다 다른 기준이었고, 미리 지은 것은 마지막 덩어리 하나만 맞았다.

0.3.428 로그 (논문 `6c1cc930d02f`):

- 첫 문장 마지막 덩어리(127자)는 처음 묻자마자 `ready` — 미리 지은 것이 맞았다.
- 나머지 덩어리 25·62·95자, 다음 문장 29·70·89·120·129자는 모두 `queued` 후 15–20초 뒤 `ready`.
- 한 번은 아직 안 지어져서 `sound_ref_missing` 으로 채점이 빠졌다.
- 그동안 미리 짓기는 13초에 하나씩 문장을 지어서 22분에 100개를 지었다. 일은 했지만 연습이 묻는 글이 아니었다.

0.3.428 은 기준 형식(분포)이 바뀌어 예전 기준이 모두 무효가 됐고, 논문을 다시 열 때까지 다시 짓지 않았다. 이것은 형식 변경 때마다 한 번 생기는 일이고, 위 문제는 늘 있었다.

## 고친 것

폰은 덩어리와 함께 그 문장의 마지막 덩어리를 `whole_text` 로 보낸다.

서버(`/api/tts/spoken`)는
1. 덩어리 자체 기준이 있으면 그것 (`ready`)
2. 없으면 문장 기준에서 덩어리에 들어가는 단어만 쓴다 (`sliced`)
3. 둘 다 없으면 **문장**을 짓는다. 한 번 지으면 그 문장의 모든 덩어리가 쓴다.

빌려 쓰는 것은 덩어리의 말소리 형태가 문장 말소리 형태의 앞부분이고 단어 경계에서 끝날 때만이다 (`whole_line`). 괄호 안에서 잘린 덩어리는 정규화가 다르게 읽으므로 예전처럼 자기 기준을 짓는다. 단어 위치(lo/hi)가 같으니 `attach_sounds` 가 그대로 덩어리 단어에 준다.

증거 `practice_skill_align` 에 `sound_ref_whole` (`front` · `not_front` · `same` · `none`).

## 잘라 써도 되는가 — 실측

0.3.428 에서 지어진 기준 100개 중 한쪽이 다른 쪽의 앞부분인 쌍 23개, 단어 193개:

| | 값 |
|---|---|
| 소리 줄이 똑같은 단어 | 81% |
| 덩어리 끝 단어가 똑같은 비율 | 78% (18/23) |
| 소리가 같을 때 분포 겹침, 끝 단어 아닌 것 | 평균 0.977, 하위 10% 0.941 |
| 소리가 같을 때 분포 겹침, 끝 단어 | 평균 0.964, 하위 10% 0.873 |
| 다른 단어의 소리 유사도 | 평균 0.71, 대부분 소리 수 같고 하나 바뀜 |

다른 19% 는 덩어리 끝에 몰려 있지 않다. 두 번 합성하면 생기는 차이다. 끝 단어는 문장 중간 억양으로 읽힌 것이 되지만 분포 차이는 0.96 수준이다.
