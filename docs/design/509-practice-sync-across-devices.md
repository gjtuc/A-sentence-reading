# design/509 — 연습 기록 기기 사이 동기화: 캘린더 더하기, 연습 위치 (0.3.519)

## 확인한 것

- 연습 캘린더·난이도는 design/250으로 이미 서버(`users/{uid}/practice/focus_v1.json`)에 올리고 받는다. 20일 기록에 push/pull 모두 ok.
- 캘린더가 비어 보인 건 10월 13일 이후 `focus_block_done`이 한 번도 없어서다. `focus_session_start`는 있었다(3분 블록을 끝까지 채우지 못함).

## 문제

1. 합치기가 날짜마다 큰 쪽을 골랐다. 폰 3블록 + 웹 2블록이 같은 날이면 3이 됐다.
2. 논문별 연습 위치(design/246)는 기기에만 있었다.
3. 열려 있는 연습 화면은 다른 기기 기록을 다시 읽지 않았다.

## 결정

- 캘린더에 `by_dev`(기기 id → 날짜 → 블록 수)를 둔다. 같은 기기는 큰 쪽, 다른 기기는 더한다. `days`는 기기 합보다 작아지지 않는다. 기기 id는 spot 기기 id(design/411). 서버·앱이 같은 규칙(`merge_focus_stores` / `mergeFocusHistories`). 기기 최대 20.
- 기기 줄이 없던 예전 기록은 `days`에 그대로 남는다. 그날 처음 블록을 끝내는 기기는 다른 기기 몸을 뻐 나머지를 자기 것으로 가져간다(`focusAddBlock`).
- 캘린더를 열면 서버에서 다시 받고 화면이 들고 있던 기록과 합친다(`refreshFromCloud`).
- 연습 위치는 읽기 위치 통로(`/api/spots`)에 `p.<cache id>`로 실는다. `si`=문장, `fi`=조각. 서버 변경 없음. 받은 기기는 더 새로울 때만 자기 연습 위치로 저장하고 다음 연습 때 거기서 시작한다. 열려 있는 연습 화면은 움직이지 않는다. 샘플 라운드(`#r`)는 싣지 않는다.
- 녹음(takes)은 옮기지 않는다. 소리 파일이라 크고 비용이 든다.

## 시험

- `tests/test_practice_cloud_sync_250.py` — 두 기기 더하기, 예전 기록 그대로, 나쁜 기기 id 버림, `p.` 키 허용.
- `mobile/test/focus_practice_test.dart` — 폰 3 + 웹 2 = 5, 예전 블록 이어받기, 블록이 이 기기 줄에.
- `mobile/test/spot_sync_test.dart` — 연습 위치 키, 올리기·따라가기 연결, 캘린더 열 때 다시 받기.
