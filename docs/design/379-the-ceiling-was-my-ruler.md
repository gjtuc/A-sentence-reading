# 379 — 천장이 낮았던 게 아니라 내 자가 틀렸다

## design/377 이 틀리게 적은 것

design/377 은 이렇게 적었다.

> 완벽한 낭독도 0.77–0.84 밖에 못 받는다. 사장님의 정성스러운 녹음은 0.78 이었으니
> **이미 천장에서 읽고 있다**. 모자란 0.22 는 읽기가 아니라 측정이다.
>
> 24단어 중 3개는 어떻게 읽어도 통과선을 넘을 수 없다 —
> `nanoparticles` 0.429, `c v d` 0.500, `vapor` 0.600.

**둘 다 틀렸다.** 천장은 1.000 이고, 통과 못 하는 단어는 없다.

## 틀린 이유

소리 모델은 이중모음을 **한 덩어리**로 줄 때가 있다 — `oʊ` 가 기호 하나다. 반대로
단어 하나를 소리 하나씩 길게 늘어놓을 때도 있다. 두 줄을 비교하려면 **양쪽을 같은 방식으로
잘라야** 하고, 그걸 하는 함수가 `split_phone_units` 다. 글자마다 칸을 열므로 `oʊ` 는 두 칸이
된다.

design/377 의 천장 탐침은 **기준만 잘랐다**. 원어민 낭독은 모델이 준 덩어리 그대로 뒀다.
그래서 문장에 든 이중모음 하나하나가 전부 틀린 소리로 셈됐다.

| | design/377 (한쪽만 자름) | 같은 방식으로 자름 |
|---|---|---|
| 같은 목소리·같은 문장 | 0.841 | **1.000** |
| 같은 목소리, 더 느리게 | 0.813 | **0.963** |
| 다른 미국 남성 | 0.803 | **0.961** |
| 미국 여성 | 0.818 | **0.968** |
| 영국 | 0.770 | **0.917** |

단어별로도 24개 전부 1.000 이다. `nanoparticles` 가 0.429 였던 것은 그 단어의 14개 소리 중
8개가 이중모음 쪼개짐 때문에 어긋났기 때문이다.

## 왜 바로 안 보였나

기준 단어의 소리는 `hand_out` 에서 `natural[k:j]` — 그 문장을 그냥 읽은 소리 줄을 **잘라낸
조각**이다. 그리고 합성은 완전히 재현된다(오디오 바이트까지 같다, `ceiling_cause_probe.py`).
그러니 기준은 같은 낭독 안에 **통째로** 있어야 하고 점수는 1.000 이어야 한다. 그게 아니었던
것이 실마리였다.

`ref_slice_probe.py` 로 재보니 24개 중 8개만 통째로 들어 있었다. 틀린 후보를 하나씩 지웠다 —
목소리는 양쪽 다 `en-US-Neural2-D` 였고(`ASR_REF_VOICE` 는 live 에 없다), 본뜨기 쪽 낭독에도
없었고(0/24), 문장을 로컬에서 새로 지으면 22/22 가 통째로 들어 있었다. 남은 건 **기호를
세는 방식**뿐이었고, `ref_symbol_probe.py` 가 그걸 보여줬다 — 라이브 기준 쪽에만 있는 소리
7종(`o`, `u`, `ʊ`, …)과 낭독 쪽에만 있는 소리 10종(`oʊ`, `uː`, …)의 **개수가 정확히 맞아떨어졌다**
(`oʊ` 3개 ↔ `o` 3개 + `ʊ` 3개).

## 라이브 채점은 멀쩡하다

폰은 **양쪽을 다 자른다**. 그래서 `sound_align_probe.py` 가 로그만으로 25칸 중 25칸을
재현할 수 있었다. 이 버그는 **내 탐침 안에만** 있었고 제품에는 없다.

design/377 의 나머지는 그대로 유효하다 — 앞 0.641 / 뒤 0.374 기울기, 턱걸이 셈,
`electrochemical` 이 0.003 차로 떨어진 것, `slot_scores` 기능.

## 그래서 지금 상황

- 통과 못 하는 단어는 없다. 고칠 것이 없다.
- 맞는 낭독은 0.92–0.97 을 받고, 24단어 중 23~24개가 통과선(0.603)을 넘는다.
- 옛 통과선 0.72 로도 맞는 낭독은 21~24개를 넘긴다. design/375 가 적은 「0.72 에서 완벽한
  낭독이 19–38% 를 떨어뜨린다」도 같은 버그에서 나온 숫자다.
- 사장님의 읽기-전체 녹음 0.78 은 **측정 바닥이 아니라 실제 읽기**다. 맞는 낭독 0.95 와
  0.17 차이가 있고, 그건 측정이 아니라 발음 차이다. 점수가 실제로 무언가를 재고 있다는 뜻이다.

## 고친 것

잘못 재는 탐침을 그냥 두면 다음에 또 같은 답이 나온다. `score_ceiling_probe.py` 와
`ceiling_per_word_probe.py` 는 양쪽을 자르도록 고쳤다. 고친 뒤 per-word 천장은 24/24 가
1.000 이다.

## 재볼 것

```
python scripts/ceiling_recheck_probe.py .cache/ev416.jsonl 5   # 틀린 자 vs 바른 자
python scripts/ceiling_voices_probe.py  .cache/ev416.jsonl 5   # 다른 맞는 낭독의 점수
python scripts/ceiling_cause_probe.py --lines 2                # 합성이 재현되는지
python scripts/ref_slice_probe.py      .cache/ev416.jsonl 5    # 기준이 낭독의 조각인지
python scripts/ref_symbol_probe.py     .cache/ev416.jsonl 5    # 양쪽이 같은 소리를 쓰는지
```

## 규칙

**두 소리 줄을 비교하기 전에, 양쪽이 같은 방식으로 잘렸는지 먼저 확인할 것.** 모델은 같은
소리를 덩어리로도 낱개로도 준다. 한쪽만 자르면 문장의 이중모음 수만큼 점수가 깎이고, 그
깎인 양이 하필 「사람이 못 읽는 정도」처럼 보인다.

IPA 를 Windows 콘솔에 찍지 말 것 — `ref_symbol_probe.py` 처럼 `\uXXXX` 로 찍으면 된다.
