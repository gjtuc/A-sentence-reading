# 454 — USB 와 서버 길을 같이 기다리기, 옛 웹 창 알리기 (0.3.474)

## 문제

USB 로 동기화했더니 웹과 폰 모두 3분 뒤 "연결하지 않았습니다" 로 끝났다. 서버 길로 넘어가지도 않았다.
증거(`near_sync_done`, 14:17~14:20 UTC):

- 폰 0.3.473: `usb: 1`, `usb_no_web` — 도우미에 붙었고, 웹이 도우미에 없고 서버 연결도 없어서 도우미에서 3분 기다림.
- 웹 **0.3.472**: `usb` 필드 없음, `no_phone` — 배포 전에 연 창이라 옛 코드. USB 를 모르고 서버 연결만 만들고 기다림.
- 폰이 웹보다 3초 먼저 시작해서, 폰이 서버를 볼 때는 웹의 연결이 아직 없었다.

도우미와 선은 정상이었다(폰 `nc` 로 hello·paired 를 받음). 둘이 서로 다른 길에서 기다린 것이 원인이다.

## 바꾼 것

- 폰(`join`): 도우미에 웹이 있으면 USB. 없으면 서버 연결을 찾고, 없으면 도우미에서 기다리면서 **1.5초마다 서버 연결도 다시 찾는다** (`_waitUsbOrLink`). 웹의 서버 연결이 생기면 USB 를 닫고 그 길로 간다.
- 웹(`host`): 도우미에 폰이 이미 있으면 USB 만. 폰이 꽂혀 있지만 아직 안 왔으면 서버 연결도 만들고 **둘 다 기다린다** (`_awaitAnswer(usb:)`). 먼저 오는 쪽으로 가고, USB 가 이기면 서버 연결을 지운다.
  서버 쪽 준비가 실패해도 도우미가 있으면 USB 로 계속 기다린다.
- 웹은 동기화 전에 서버 버전을 본다. 이 창보다 새 버전이 있으면 "새 버전이 나왔어요" 를 띄우고 새로고침을 권한다 (`nearReloadPage`). 서버를 못 보면 그냥 진행한다.
