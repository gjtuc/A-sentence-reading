# design/384 — 어느 소리가 빠졌는지

## 문제

틀린 단어 연습은 단어 하나만 보여 준다. 문장 읽기에서는 틀린 단어를 노랗게 칠해 주지만, 그 단어 안에서는 **어느 발음기호를 집중해야 하는지** 알 수 없다. `This sound` 줄은 한 번 더 틀린 뒤에야 뜨고, 고르는 방법도 기준 기호와 들린 기호를 글자로 맞춰 보는 옛 방식이다.

단어 점수는 소리들의 평균이다. `prepared` 가 45점이면 그 안에 `ɛ` 가 11점인지는 보이지 않는다.

## 1차 (0.3.423) — 첫 시도부터 강조

서버가 이미 소리 하나하나의 확신도를 계산한다 (`sound_score_of` 의 `sure` 목록). 지금까지는 평균과 최솟값으로 압축하고 개별 값은 버렸다. 단어 하나의 소리는 보통 8~12개라 그대로 보내도 부담이 없다.

### 서버

`sound_score_of` 가 `each` 를 같이 돌려준다. `_slot_certainty` 가 `slot_each` 로 보낸다.

```
95 88 11|76 80|-
```

단어는 `|` 로, 그 안 소리는 공백으로. 모델이 모르는 단어는 `-` 하나. 막대가 단어 수를 세므로 `slot_sym` 과 칸이 맞는다. `each` 가 없는 옛 답도 `-` 로 받아 깨지지 않는다.

### 폰

`parseSlotSounds` 가 그 줄을 칸마다 숫자 목록으로 푼다. 칸 수가 안 맞으면 **줄 전체를 버린다** — 밀리면 옆 단어의 소리를 칠하게 된다.

`MissedWordSpan.sounds` 에 문장 읽기 때의 그 칸 숫자를 실어 둔다. 틀린 단어 화면에 들어가는 순간부터 통과선 아래 기호를 빨갛게 밑줄 친다. 문장 읽기 모드에는 안 넣는다.

기호 개수와 숫자 개수가 안 맞으면 칠하지 않는다. 모델 사전에 없는 소리는 서버가 버리므로, 억지로 맞추면 엉뚱한 기호가 빨개진다.

## 2차 — 사다리와 0.5배

같은 소리를 단어 연습에서 두 번 연속 틀리면 그 소리 연습으로 내려간다. 화면에는 그 기호를 크게, 단어는 작게. 들려주는 소리는 **단어 전체**를 폰 재생기로 0.5배 (TTS를 다시 부르지 않는다. design/371 — 소리로 경계를 자르지 않는다).

판정은 그 소리 하나의 확신도만 본다. `noteMissReview` 는 통과선을 건드리지 않으므로 소리 연습 점수는 계정 선에 안 들어간다. 소리당 2번. 맞추거나 두 번을 쓰면, 같은 단어에 대기 중인 다른 소리가 있으면 그쪽으로, 없으면 단어 연습으로 올라온다.

`MissReviewLadder` 가 그 상태만 들고, 화면은 재생과 녹음만 한다. 기호 수와 숫자 수가 안 맞으면 사다리를 열지 않는다.
