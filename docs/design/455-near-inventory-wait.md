# 455 — 상대 목록은 내 목록이 준비된 뒤에 본다 (0.3.475)

## 증상

폰 보관함에서 지운 논문이 USB 동기화 뒤에도 웹에 남았다.
같은 동기화에서 웹은 이미 가진 논문을 폰에서 다시 받았다 (`library_index_upsert` remove → upsert, 웹 `papers_in 1`).

## 원인

`NearSync.run` 은 받기를 먼저 켜고, 내 논문 목록 · 지운 기록 · 숨긴 논문을 읽은 뒤 `inv` 를 보낸다.
웹은 이 읽기가 느리다 (논문마다 저장된 세션을 확인한다). USB 는 빨라서 폰의 `inv` 가 그 전에 도착했고,
`_onInventory` 가 빈 `_mine` 으로 계산했다.

- 내 것 중 지울 것: 비교할 내 것이 없으니 0개 (design/450 의 지우기가 안 퍼짐)
- 받을 것: 이미 가진 논문도 "없는 것" 으로 보고 다시 요청

서버 경로는 지연이 길어 숨겨져 있었다.

## 바꾼 것

`_ready` 는 내 목록이 다 채워지면 끝난다. 그 전에 온 `inv` 는 `_ready` 뒤에 처리한다.
`inv` 말고는 일찍 올 수 있는 메시지가 없다: 상대의 `want` · `paper` 는 내가 보낸 `inv` · `want` 에 대한 답이다.

## 증거

`near_sync_done` 에 더함:

- `gone_out` / `gone_in`: 보낸 / 받은 지운 기록 수
- `forget_failed`: 받은 지우기를 여기서 적용하다 실패 (전에는 조용히 삼켰다)
- `inv_wait_ms`: 상대 목록을 붙잡아 둔 시간 (0 이 아니면 이 경쟁이 실제로 일어난 것)

## 시험

`mobile/test/near_gone_test.dart` 마지막 시험: 목록 읽기가 300 ms 걸리는 쪽이 지울 것을 지우고, 가진 논문은 다시 받지 않는다.
