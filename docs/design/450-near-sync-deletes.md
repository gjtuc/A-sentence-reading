# 450 — 한쪽에서 지운 논문은 동기화 때 다른 쪽에서도 지운다 (0.3.473)

## 문제

폰에서 보관함 논문 2개를 지우고 「웹과 동기화」를 눌렀더니, 웹에서 지워지지 않고 오히려 웹이 그 2개를 폰으로 다시 보냈다.
near sync(design/410)는 "가진 것을 서로 채운다"만 했다. 지운 기록이 없어서, 지운 쪽은 그냥 "없는 쪽"으로 보였다.

## 규칙

- 각 기기는 지운 논문을 기억한다: 논문 id → 지운 시각(ms). `near_gone_v1_<uid>` (SharedPreferences, `near_gone_store.dart`). 최근 2000개까지.
  지우기가 서버에서 끝난 논문(`deletePapers` 의 성공 id)을 적는다.
- 각 기기는 논문이 처음 들어온 시각을 기억한다: 색인의 `added_at` (`PaperDiskIndexEntry.addedAt`). `upsertIndex` 가 처음 넣을 때만 찍고, 고칠 때는 그대로 둔다.
  이 필드 전에 있던 논문은 비어 있고 0 으로 센다(어떤 지우기보다 오래됨).
- `inv` 에 `gone`(지운 기록)과 논문마다 `added` 를 싣는다.
- 상대가 이 논문을 **여기 들어온 뒤에** 지웠으면(`상대 gone ≥ 내 added`) 여기서도 지운다.
- 내가 이 논문을 **상대에게 들어온 뒤에** 지웠으면 받지 않는다.
- 지운 뒤에 다시 가져온 논문은 `added` 가 지운 시각보다 늦으므로 새 논문으로 퍼진다. 옛 사본은 지우고 새 사본을 받는다.
- 지운 기록은 서로 합친다(같은 id 는 늦은 시각).
- 휴지통에 있는(아직 되돌릴 수 있는, design/224) 논문은 보내지도 받지도 않는다. 20초(design/453)가 지나 실제로 지워진 뒤의 동기화부터 퍼진다.
- 옛 버전 앱(지운 기록이 없음)과 맞춰도, 여기서 지운 논문은 다시 받지 않는다.

## 여기서 지우기

`LibraryController.forgetFromNear(gone, drop)`:
지운 기록을 합치고, `drop` 논문의 기기 파일·문서 사본·연습 기록·책갈피를 지우고, 서버 삭제를 뒤에서 요청한다(대개 이미 지워져 있다).
동기화 창을 닫을 때 그 서버 삭제를 최대 20초 기다린 뒤 새로고침한다. 아니면 서버 목록이 논문을 되살린다.
결과 줄: "다른 기기에서 지운 논문 N개를 여기서도 지움". 증거 `near_sync_done` 에 `papers_gone`.
